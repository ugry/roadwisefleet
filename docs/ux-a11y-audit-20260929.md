# UX + accessibility audit — pilot surfaces (board task #70, FAv1-UX1)

Date: 2026-09-29 · Author: Max Cooper (developer) · Branch: `agents/max-ux-a11y`

Scope (the live surfaces, audit on the source of truth in `ugry/roadwisefleet`):

| Surface | Live URL | Source |
| --- | --- | --- |
| Pilot landing | `https://roadwisefleet.com/pilot/` | `pilot/index.html` |
| Pilot dashboard | `https://roadwisefleet.com/pilot/dashboard.html` | `pilot/dashboard.html` |
| Pilot driver PWA | `https://roadwisefleet.com/pilot/driver.html` | `pilot/driver.html` |

Method: the audit ran the `ux` MCP server (`@elsahafy/ux-mcp-server` 5.0.0) against the
real markup/styles, plus a WCAG 2.1 contrast re-derivation for the OKLCH palette
(the `ux` contrast tool takes hex/rgb). The palette was authored in OKLCH, so
`scratch/ux-a11y-colors.py` converts each token to sRGB and feeds the exact pairs to
`ux_check_contrast`. Every FAIL below is either fixed on this branch or explicitly
deferred with a reason. The fixes carry a dependency-free regression test,
`apps/api/src/ux-a11y.test.js`, so the no-install CI job guards them.

## Tool calls used

| # | Tool call | Purpose |
| --- | --- | --- |
| 1 | `ux_analyze_accessibility` (level `AA`) on `pilot/index.html`, `app/index.html`, `pilot/dashboard.html` markup | static WCAG pass (0 issues each) |
| 2 | `ux_check_responsive` (`all`) on the dashboard, driver, Fleet Manager and tracking markup | viewport / touch-target / breakpoint / reflow review |
| 3 | `ux_check_contrast` (level `AA`) on 9 foreground/background pairs | before/after contrast ratios |
| 4 | `ux_review_usability` on the dashboard (sign-in → create trip → trips table → drawer) | Nielsen heuristic review |
| 5 | `ux_audit_design_system` (`all`) on the colour/type/spacing/touch tokens | token consistency |
| 6 | `ux_generate_accessibility_report` for `/pilot/dashboard.html` (AA) | coverage checklist (images, forms, colour, keyboard, focus, headings, links, language) |
| 7 | `ux_suggest_error_message` (authentication → 401) | error-copy check |

`ux_analyze_accessibility` reports **0 static issues** on every page: the markup itself
(doctype, `lang`, viewport, labels, table headers, landmarks) is clean. The failures
below are in colour, focus/keyboard behaviour, dialog semantics, live regions, target
sizes and motion — the checks `ux_check_contrast`, `ux_check_responsive` and
`ux_generate_accessibility_report` name, and which a static parse cannot see.

### Focus (WCAG 2.4.7) — FAIL → FIXED

The pilot pages set `input:focus,select:focus{outline:none; box-shadow:0 0 0 3px accent/.55}`
and gave links, buttons and cards no custom ring; `ux_check_responsive` and
`ux_generate_accessibility_report` both list "visible focus indicators". The amber
55% ring over white measures ≈1.4:1 (computed `#f8d473` vs `#ffffff`), i.e. not
reliably perceivable. Added `:focus-visible{outline:3px solid var(--accent-deep)}`
(solid, 7.08:1 on white) to `pilot/index.html`, `pilot/dashboard.html`,
`pilot/driver.html`; `app/app.css` already had a solid `:focus-visible` ring.

### Keyboard reachability of the trip rows (WCAG 2.1.1, 2.4.3) — FAIL → FIXED

`pilot/dashboard.html` `tr.clickable[data-open]` and the Fleet Manager
`app/app.js` `tr.clickable[data-trip]` opened the trip detail on **click only**;
the rows are not focusable, so keyboard users could not open a trip.
Fix: the route cell is now a real `<button class="row-open">` / `<button class="cell-open">`
that opens the same detail (styling unchanged), and the dashboard drawer wiring
handles it. `verify-trips-view.js` still sees one `tr[data-trip]` per row.

### Dashboard drawer semantics and focus (WCAG 2.1.1, 2.4.3, 4.1.2) — FAIL → FIXED

`#drawer` was `aria-hidden="true"` while closed but still contained the focusable
`#drawerClose` (an `aria-hidden`-focus violation), had no dialog role, never moved
focus in, never returned it, and let Tab wander behind the overlay.
Fix: `role="dialog" aria-modal="true" aria-labelledby="drawerTitle" tabindex="-1"`;
`.drawer` is `visibility:hidden` when closed (out of tab order and the a11y tree);
`openDrawer()` focuses the dialog, `closeDrawer()` restores the opener's focus, and a
Tab trap cycles within the open dialog.

### Live region for dynamic status (WCAG 4.1.3) — FAIL → FIXED

`pilot/dashboard.html` `#globalMsg` had no role, so "trip created / moved /
error" messages were never announced. Fix: `role="status" aria-live="polite"`.
(`pilot/driver.html` already had `role="alert"`; the Fleet Manager views have
per-view `role="alert"` regions and the driver view has `role="alert"`.)

### Touch targets ≥ 44px (WCAG 2.5.8 / 2.5.5) — FAIL → FIXED

`ux_check_responsive` recommends ≥44×44px on every surface; measured pre-fix boxes
from the CSS:

| Control | Before (computed box) | After (coarse pointer) |
| --- | --- | --- |
| `pilot/dashboard.html` `button.small` (12px + 5px/9px padding) | ≈29px | `min-height:44px;min-width:44px` |
| `pilot/dashboard.html` `select.lang-switcher` | ≈29px | `min-height:44px` |
| `pilot/driver.html` `button.small` | 36px (hard value) | 44px |
| `pilot/driver.html` `select.lang-switcher` | 36px | 44px |
| `app/app.css` `.doc-actions button`, `.track-actions button` (13px + 6px/10px) | ≈32px | `min-height:44px;min-width:44px` |
| `app/app.css` `.driver-tab`, `.driver-action`, `.nav-item`, controls | 36–41px | `min-height:44px` |

Added a `@media (pointer: coarse)` block to `pilot/dashboard.html`,
`pilot/index.html` and `app/app.css` (and the hard 44px in the mobile-first driver
page), so the desktop layout keeps its compact sizing.

### Reduced motion (WCAG 2.3.3) — FAIL → FIXED

No surface honoured `prefers-reduced-motion` (the landing card lift, the drawer and
overlay slide, the driver sync `pulse`). Added a `@media (prefers-reduced-motion: reduce)`
override to all four sources. The tracking page has no transition/animation, so it
needs none (PASS).

### Heading hierarchy (WCAG 1.3.1 / 2.4.6) — FAIL → FIXED

`app/app.js` driver view (`/app/my-trips`) went `<h1>` → `<h3>` in
`driverChecklistHtml` and `driverCaptureHtml` (level skipped). Both are now `<h2>`.
The other views and the pilot pages are ordered correctly (PASS).

### Half-built tablist (WCAG 4.1.2, 4.1.1) — FAIL → FIXED

`app/app.js#myTripsSwitcherHtml` rendered `role="tablist"` / `role="tab"` with no
`aria-controls`, no tabpanel and no arrow-key handling. Replaced with a plain
`role="group"` + `aria-pressed` toggle-button list — correct for the actual
behaviour, keyboard-operable, no redesign.

### Control semantics for sign-out — FAIL (minor) → FIXED

`pilot/driver.html` rendered sign-out as `<a href="#" id="logout">`. It is an action,
not navigation; now a `<button class="ghost-link">` (same look).
